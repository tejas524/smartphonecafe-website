**Status:** complete.
**Purpose:** record exactly what moved, what deliberately did not, and the
evidence that nothing was lost.

---

## Intentionally left in place

- **`shop photo/`** stays at the repository root. These nine files are the
  owner's unretouched originals - source material, not part of the deployed
  frontend bundle. Keeping them where they were means every existing document
  and reference to `shop photo/` stays correct.
- **`_tools/`** stays at the root and remains git-ignored. It is local scratch
  tooling (browser harnesses, OCR helpers), not part of the shipped project.
- **`docs/`** stays at the root; it documents the whole repository.
- **`.npm-cache/`** stays at the root and remains git-ignored.

## Issues encountered

1. **`git mv` on `src/` and `public/` failed with "Permission denied."** A stray
   Vite dev server from the earlier session (plus its orphaned `esbuild` service)
   still held directory handles on them. Neither was started by this session.
   The processes exited on their own; the retry then succeeded. The first
   attempt did move the five individual files, so no state was lost.
2. **`fileURLToPath` was briefly undefined** in the refactored pipeline because
   the import edit was rejected and not re-applied. Caught by re-running the
   pipeline, which failed loudly; fixed by adding the import. A verification
   run that only compared output hashes had reported a false PASS because the
   script died before writing anything - the check was rewritten to assert on
   the exit code first.
3. **npm auto-created a root `package-lock.json`** with a folder-derived name
   (`SmartPhone Cafe`). Regenerated properly via
   `npm install --package-lock-only` so it matches the real package name.

## Not done, and not claimed

The database schema, seed data, Express API, authentication, admin dashboard and
public-site redesign are **not** implemented. `backend/` and `database/` contain
only a README. Nothing in the running site reads from a database.
